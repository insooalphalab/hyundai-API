# 시트룸 — 좌석마다 나만의 방 (Pleos Connect 시뮬레이션 앱 0.9.0)

개념 문서(`../docs/CONCEPT_v3_integrated.md`, `../docs/DATA_inventory_unused.md`)의 **1단계(SDK만으로 가능한 기능)**를 담은 첫 APK.

## 들어간 기능
| 화면 | 기능 | 쓰는 신호 |
|---|---|---|
| 방 | 좌석별 모드: 침실(「잠들었어요」) / 서재(운전석) / 기본(되돌리기) | 설정 온도·바람·열선·통풍·앰비언트 밝기 (제어) |
| 방 | CO₂ 추정(센서 없이) + "잠깐 외기로" | 좌석 점유, 내기 순환, 바람, 시간 |
| 방 | 졸음 자구책 → 15분 휴식 권고 배너 | 주행 중 운전석 창문 열기·온도 내림·바람 세게 |
| 평소의 나 | 4축: 수행(조향 방향 전환/분), 자세(주행 중 좌석 고침), 시야 보상(수동 상향등 시간), 계획(깜빡이→조향 간격) | 조향각, 좌석 위치 7종, 상향등 상태+스위치, 방향지시등 |
| 평소의 나 | 운전자 A/B/C 구분, 주행 10회부터 평소와 비교(±2σ) | 기어(D→P = 주행 1회) |
| 평소의 나 | 어르신 방(승하차 시간), 열 감각(온도를 낮춘 시점의 실내 온도, 더운데 조작 없음), 귀가 전 머무름, 공조 다툼 | 문, 좌석 점유, 실내·설정 온도 |
| 기록 | 들어오는 신호, 제어 결과, 이 차에서 안 되는 신호 | — |

모든 신호와 판정은 차 안에 날짜별 JSONL로 저장한다(본인만 열람).

## 설치·실행 (에뮬레이터 PC)
1. Pleos Connect 에뮬레이터를 Cold boot로 켠다.
2. `adb install -r dist/seatroom-0.9.0-debug.apk`
3. 앱 목록에서 **시트룸** 실행.

## Virtual Console로 시험하기
`adb forward tcp:8088 tcp:8088` → `http://127.0.0.1:8088/`
- **주행 1회 만들기:** Gear를 D → (조작) → P. 1분 이상이어야 기록된다.
- **수행:** D 상태에서 Steering Wheel 각도를 좌우로 여러 번 바꾼다.
- **계획:** 방향지시등 LEFT → 몇 초 뒤 조향 90° 이상.
- **승하차:** 동승석 도어 열기 → 좌석 점유 ON(탑승 시간 기록).
- **귀가 전 머무름:** P로 바꾼 뒤 시간이 지나 운전석 도어 열기.
- **공조 다툼:** 운전석 설정 온도 내림 → 10분 안에 동승석 설정 온도 올림.
- **CO₂:** 좌석 점유 3~4개 + 내기 순환 ON → 몇 분 뒤 1,500 ppm 넘으면 "잠깐 외기로" 버튼.
- 실내 온도(현재 온도) 카드는 Virtual Console에 없어 열 감각 기능은 에뮬레이터에서 값이 안 들어올 수 있다.

## 화면 구성 (0.6.0~: HTML 화면 + 차 신호 연결)
- 화면은 `design/seatroom-screens.html` 하나. 빌드할 때 `app/src/main/assets/seatroom.html`로 복사되어 앱 안 WebView로 뜬다(브라우저에서 열면 같은 화면이 시뮬레이션만으로 돈다).
- 앱이 0.5초마다 차 신호를 `window.onCar(json)`으로 넘기고, 화면 조작은 `window.Android.*`로 차에 보낸다.

| Virtual Console에서 | 화면에서 |
|---|---|
| Gear D/R ↔ P | 주행 중 화면 ↔ 방 화면 (주행 제한이 걸려도 주행 중 화면) |
| 좌석 점유 OFF → ON | 그 자리에 사람 표시. 주인 없는 자리면 손님 판정 시작 |
| 좌석 점유 ON → OFF | 빈자리로. 손님 기록은 지움 |
| 설정 온도·바람·열선·통풍을 직접 바꿈 | 그 자리 패널에 "이번 탑승(차 신호): 직접 고친 N회" (앱이 방 모드로 바꾼 3초는 빼고 셈) |
| 내기 순환 ON/OFF | 공기 줄의 내기·외기 표시 |
| D → (조작) → P, 1분 이상 | 평소의 나 탭으로 넘어가 그 주행의 4축 값을 시나리오 사람의 평소와 비교, "실제 주행 · 알림…" 표시. 규칙에 걸리면 시스템 알림 |

- 방 모드 버튼(운전·휴식·기본·집중)을 누르면 그 자리 주인에게서 배운 온도·바람으로 실제 공조·시트·조명을 바꾼다.
- 탑승은 **바뀌는 순간**만 반영한다(앱을 켤 때 에뮬레이터의 점유 값으로 시나리오 좌석을 지우지 않게).
- 수행 축은 5분 이상 주행해야 값이 생기고, 계획 축은 깜빡이→조향 3번 이상이 있어야 생긴다. 없으면 그 칸은 "오늘 기록 없음".
- 자리 학습 그래프·손님 판정 근거(좌석 9cm 이동 등)·몇 주 추세·CO₂ 숫자는 아직 가상 값.

## 화면 구성 (0.5.0, Compose — 0.6.0에서 HTML로 교체)
- 차 화면은 그림 위주 두 탭: **방**(위에서 본 차, 자리를 누르면 침실·서재 전환, 공기 게이지, 휴식 상태) / **평소의 나**(4축 띠 게이지, 알림 미리보기, 몇 주 추세).
- 세부 내용(주행 목록, 4축 그래프, 승하차·열 감각·머무름, 안 되는 신호)은 위쪽 **휴대폰으로 보고서** 버튼 → HTML 보고서. 시뮬레이션에서는 차 안에 저장: `files/reports/latest.html`
  - 꺼내기: `adb shell run-as com.seatroom.app cat files/reports/latest.html > report.html`
  - 견본: `dist/report-sample-senior.html`
- 신호 로그는 개발자용: 제목 "시트룸"을 길게 누르면 열리고 닫힌다.

## 시나리오 시뮬레이션 (0.4.0~)
앱을 켜면 먼저 시나리오를 고른다. 고른 조건으로 **지난 30일을 가상 주행**해 평소를 만들고, 방 설정과 알림 규칙이 달라진다.

| | 1. 가족 · 10만 km 넘은 안전운전자 | 2. 개인 · 고령 운전자 | 3. 가족 · 2인, 번갈아 운전 |
|---|---|---|---|
| 탑승 | 운전석·동승석·뒷좌석 2 | 운전석 | 운전석·동승석 |
| 방 설정 | 뒷좌석 둘 침실, 운전석 서재 | 기본 | 운전석 서재 |
| 운전자 | 아빠: 매우 꾸준(평소 폭 좁음) | 어르신: 마지막 2주 시야·계획이 천천히 변함, 더위 무반응 경향 | 지수·민호: 습관·좌석 위치가 다름 |
| 알림 규칙 | 축 2개 이상 동시에 ±2σ | 축 1개라도 ±2.3σ(최근 10회와 비교) + 몇 주 추세(따로) + 더운데 조작 없음 | 좌석 위치로 운전자 자동 구분 → 각자 평소와 ±2σ |

"평소의 나" 탭 → **오늘 주행 시뮬레이션: 평소 같은 날 / 평소와 다른 날** → 알림 미리보기 카드(보냈는지, 왜인지)와 실제 알림.

검증(단위 테스트, 시나리오당 150회 반복):
| 시나리오 | 평소 같은 날 알림 | 평소와 다른 날 알림 | 비고 |
|---|---|---|---|
| 1 안전운전자 | 0% | 99% | 축 2개 규칙이 거짓 알림을 막음 |
| 2 고령 운전자 | 34% (축 판정 19%, 더위 무반응 사건 19%) | 100% | 더위 무반응은 시나리오상 실제로 일어난 사건. 몇 주 추세는 100% 잡힘 |
| 3 2인 교대 | 9% | 100% | 좌석 위치 구분 100/100. 두 사람 기록을 섞으면 평소 폭이 약 2~3배 넓어짐 |

## 주행 중 (0.3.0~)
- 차가 주행 중 사용 제한(CarUxRestrictions)을 걸면, 또는 기어가 D/R이면 **주행 중 보기**로 바뀐다: 큰 타일 3개(자는 사람, 공기, 쉬어 가기)와 필요할 때만 "외기로 바꾸기" 버튼 하나.
- 화면이 가려지거나 다른 앱을 써도 **백그라운드 서비스**(상태 알림 "좌석마다 차 안 상태를 보고 있어요")가 신호 수집·판정을 계속한다.
- 알림: CO₂ 추정 1,500 ppm 넘음(내기 순환일 때, "외기로" 버튼), 졸음 자구책 감지(15분 안 휴식), 주행 종료 후 평소의 나와 다른 축.
- 처음 실행 시 알림 권한을 허용해야 알림이 뜬다.
- 시스템이 이 앱을 주행 중 허용 앱으로 인정할지(`distractionOptimized`)는 차·이미지 정책에 달림. 인정하지 않아 화면이 막혀도 알림은 뜬다.

## 가상 데이터로 기준선 잡기 (0.2.0~)
"평소의 나" 탭 → **가상 데이터** 줄.
- **평소 주행 20일치 넣기:** 지난 20일, 하루 한 번 주행을 만든다. SDK 콜백과 같은 신호(기어·조향·깜빡이·좌석 위치·상향등·문·좌석 점유·공조)를 실제와 같은 판정 경로(`Insights` → `BaselineStore`)로 통과시킨다.
- **오늘: 평소 같은 주행 / 평소와 다른 주행:** 오늘 1회를 추가해 비교 결과를 본다. "다른 주행"은 조향 방향 전환 +35%, 자세 고침 약 5회, 상향등 약 4.5분, 깜빡이→조향 1.6초·순서 뒤바뀜 20%, 어르신 승하차가 더 길어짐.
- **이 운전자 기록 지우기:** 선택한 운전자(A/B/C)의 기록 전체 삭제.
- 가상 주행은 목록에 "가상"으로 표시되고, 판정 문구 앞에 [가상]이 붙는다. 신호 기록 파일(JSONL)에는 쓰지 않는다.

검증(단위 테스트 `SyntheticDriveTest`, 200회 반복):
- 평소 날에 4축 중 하나라도 "평소와 달라요"가 뜨는 비율 12% (약 8일에 한 번).
- 다른 날에 2축 이상을 잡는 비율 99%.
- 횟수가 작은 축(자세)은 표준편차 하한(`Axis.minSd`)을 둬서 한두 번 차이로는 알림이 뜨지 않게 했다.

## 알려진 제약
- 브레이크 페달은 SDK에서 눌림 여부(Boolean)만 나온다. 가속 페달은 없다.
- 기어 API(`registerGearSelection`)는 SDK에서 deprecated 표시. 동작하지 않으면 주행 단위 지표(평소의 나)가 쌓이지 않는다 → "기록" 화면의 "안 되는 신호"에서 확인.
- 제어(온도·열선·조명)는 Pleos 문서상 "준비 중"인 부분이 있어 차·에뮬레이터에서 실패할 수 있다 → "방 꾸미기 결과"에 성공/실패가 표시된다.
- CO₂ 추정의 내기 순환 환기율(시간당 6회)은 가정값. 차종별 실측 보정 전.
- 시야 보상은 같은 길의 다른 차와 비교(군집)가 아직 없다 → 지금은 본인 평소와만 비교.
